## 安全问题

Apache 软件基金会积极致力于消除针对其产品的安全问题和拒绝服务攻击。

我们强烈建议开发者在公开论坛披露这些问题之前，先将此类问题报告给我们的开发邮件列表。

请注意，该邮件列表仅应用于报告未公开的安全漏洞以及处理修复此类漏洞的流程。常规的错误报告或其他咨询请创建 [issue](https://github.com/apache/inlong/issues) 进行提交。

报告安全问题的邮件地址为：
**dev@inlong.apache.org**

## 安全模型

根据 Apache InLong 安全模型文档规范，以下几种情况不需要提交安全漏洞报告：

- **数据库中恶意数据触发的问题** — Sort 模块同步数据时，如果因为数据库中存在恶意数据内容而触发某些漏洞，不应报告为 Apache InLong 的漏洞。用户需要自行确保数据库中数据的安全性。
- **租户内成员可查看业务信息** — Manager 模块中，同一租户下的成员可以查看该租户下的所有业务信息（如 Group、Stream 等）。如果因为租户成员能查看这些信息而可能触发某些漏洞，不应报告为 Apache InLong 的漏洞。用户只需确保不让不信任的用户加入自己的租户即可。

我们欢迎提出强化代码库的建议。
