## 安全问题

Apache 软件基金会积极致力于消除针对其产品的安全问题和拒绝服务攻击。

我们强烈建议开发者在公开论坛披露这些问题之前，先将此类问题报告给我们的开发邮件列表。

请注意，该邮件列表仅应用于报告未公开的安全漏洞以及处理修复此类漏洞的流程。常规的错误报告或其他咨询请创建 [issue](https://github.com/apache/inlong/issues) 进行提交。

报告安全问题的邮件地址为：
**dev@inlong.apache.org**

## 安全模型

Apache InLong 各模块基于其设计定位，对安全边界有明确的责任划分。以下情况不属于 Apache InLong 的漏洞，无需作为安全问题提交报告（但仍欢迎提出强化代码库的相关建议）：

1. 由同步数据内容触发的漏洞

Sort 模块提供实时数据同步能力，支持在各类数据库之间读取和写入受信任的数据。除非另有约定，数据库中的恶意数据均被视为不安全输入，用户应自行确保其数据源的安全性。

2. 租户成员查看本租户内的业务信息

Manager 模块提供租户隔离能力，同一租户内的任意成员均可查看该租户下的全部业务信息，包括 Group、Sink、Stream 等。如需防止业务信息被他人查看，用户只需确保未将无关人员加入当前租户。

3. 在授权范围内执行的正常操作

在租户权限模型下，仅 Group 责任人有权对其名下的 Group、Sink、Stream 等信息进行修改和删除。成员在被授予的权限范围内执行的正常操作即属此列。

4. 因用户配置或部署不当导致的安全问题

因用户自身原因——如未正确配置租户隔离、未妥善管理成员加入、或部署环境不安全——导致的信息泄露或风险。

5. 受信任数据或受信任环境前提被破坏时引发的问题

InLong 默认运行在受信任的数据源与可信的部署环境之上。当该信任前提在用户侧被破坏时——例如接入了不可信的数据源，或开放了不应公开的访问入口——所引发的问题。
