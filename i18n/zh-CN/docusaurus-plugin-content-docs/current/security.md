## 安全问题

Apache 软件基金会积极致力于消除针对其产品的安全问题和拒绝服务攻击。

我们强烈建议开发者在公开论坛披露这些问题之前，先将此类问题报告给我们的开发邮件列表。

请注意，该邮件列表仅应用于报告未公开的安全漏洞以及处理修复此类漏洞的流程。常规的错误报告或其他咨询请创建 [issue](https://github.com/apache/inlong/issues) 进行提交。

报告安全问题的邮件地址为：
**dev@inlong.apache.org**

## 安全模型

Apache InLong 各模块基于其设计定位，对安全边界有明确的责任划分。以下情况不属于 Apache InLong 的漏洞，无需作为安全问题提交报告（欢迎提出强化代码库的相关建议）：

1. 由同步的数据内容触发的漏洞（Sort 模块） Sort 模块提供实时同步能力，支持在各类数据库中读取/写入受信任的数据。除非另有规定，数据库中存在的恶意数据均被视为不安全，用户需自行确保其数据库中的数据是安全的。凡是由同步的数据内容本身可能触发的漏洞，均属于此类情况。

2. 租户成员查看本租户内的业务信息（Manager 模块） Manager 模块提供租户隔离能力，租户的任意成员均可查看当前租户下的所有业务信息（Group、Sink、Stream 等）。用户若需保证业务信息不被他人查看，只需确保其他用户未加入当前租户即可。凡是因同租户成员可查看 Group、Stream 等信息而引发的问题，均属于此类情况。

3. 在授权范围内执行的正常操作（Manager 模块） 在租户权限模型下，只有 Group 责任人才能对 Group、Sink、Stream 等信息进行修改、删除。成员在其被授予权限范围内执行的正常操作，均属于此类情况。

4. 因用户自身配置或部署不当导致的安全问题 因用户自身原因——如未正确配置租户隔离、未妥善管理成员加入、或部署环境不安全——导致的信息泄露或风险，均属于此类情况。

5. 受信任数据 / 受信任环境前提被破坏时引发的问题 InLong 默认运行在受信任的数据源与可信部署环境之上。当此信任前提在用户侧被破坏时——如接入不可信数据源、或开放不应公开的访问入口——所引发的问题，均属于此类情况。
